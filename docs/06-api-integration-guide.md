# 6. Admin Panel API Integration Guide

> Maps every Admin Panel page to the backend API endpoints it consumes. Includes request/response formats, DTOs, query parameters, and error handling patterns.

---

## 6.1 API Overview & Base Configuration

### 6.1.1 Base URL

| Environment | Base URL |
|---|---|
| Development | `http://localhost:3000/api/admin` |
| Staging | `https://api-staging.example.com/api/admin` |
| Production | `https://api.example.com/api/admin` |

### 6.1.2 Standard Headers

| Header | Value | Description |
|---|---|---|
| `Authorization` | `Bearer <access_token>` | JWT access token |
| `Content-Type` | `application/json` | Request body format |
| `Accept` | `application/json` | Response format |
| `X-Request-ID` | `<uuid>` | Unique ID for request tracing (auto-generated by interceptor) |
| `X-Admin-Version` | `1.0.0` | Admin panel version (for API compatibility checks) |

### 6.1.3 Standard Response Envelope

**Success Response**:

```json
{
  "data": { ... },
  "meta": {
    "page": 1,
    "perPage": 25,
    "total": 1420,
    "totalPages": 57
  }
}
```

**Error Response**:

```json
{
  "errors": [
    {
      "code": "VALIDATION_ERROR",
      "message": "Title is required",
      "field": "title",
      "details": {}
    }
  ]
}
```

### 6.1.4 Standard Query Parameters

| Parameter | Type | Description |
|---|---|---|
| `page` | `number` | Page number (1-indexed) |
| `perPage` | `number` | Items per page (default: 25, max: 100) |
| `sort` | `string` | Sort field (e.g., `createdAt`, `title`) |
| `sortDir` | `'asc' \| 'desc'` | Sort direction |
| `q` | `string` | Search query (full-text) |
| `fields` | `string` | Comma-separated list of fields to include (sparse fieldsets) |

## 6.2 Authentication Endpoints

### 6.2.1 Login

```
POST /api/auth/login
```

**Request DTO**:

```typescript
interface LoginRequest {
  email: string;
  password: string;
}
```

**Response DTO**:

```typescript
interface LoginResponse {
  accessToken: string;
  expiresIn: number;          // seconds until access token expires
  mfaRequired: boolean;
  mfaMethod?: 'totp' | 'sms'; // present if mfaRequired is true
}
```

**Error Codes**:

| Code | HTTP Status | Description |
|---|---|---|
| `INVALID_CREDENTIALS` | 401 | Incorrect email or password |
| `ACCOUNT_LOCKED` | 403 | Account locked after too many failed attempts |
| `ACCOUNT_DEACTIVATED` | 403 | Admin account has been deactivated |

### 6.2.2 MFA Verification

```
POST /api/auth/mfa/verify
```

**Request DTO**:

```typescript
interface MfaVerifyRequest {
  code: string;           // 6-digit TOTP code
  trustDevice?: boolean;  // Skip MFA on this device for 30 days
}
```

**Response DTO**:

```typescript
interface MfaVerifyResponse {
  accessToken: string;
  expiresIn: number;
  refreshToken: string;
  user: AdminUser;
}
```

### 6.2.3 Token Refresh

```
POST /api/auth/refresh
```

**Request**: No body. Refresh token is sent via HttpOnly cookie.

**Response DTO**:

```typescript
interface RefreshResponse {
  accessToken: string;
  expiresIn: number;
}
```

### 6.2.4 Logout

```
POST /api/auth/logout
```

**Request**: No body. Server invalidates the refresh token.

**Response**: `204 No Content`

### 6.2.5 Current User

```
GET /api/auth/me
```

**Response DTO**:

```typescript
interface AdminUser {
  id: string;
  email: string;
  displayName: string;
  avatarUrl: string | null;
  roles: Role[];
  permissions: string[];
  lastLogin: string;        // ISO 8601
  mfaEnabled: boolean;

interface BaseExercise {
  id: string;
  type: ExerciseType;
  order: number;
  createdAt: string;
  updatedAt: string;
}

interface TranslationExercise extends BaseExercise {
  type: 'translation';
  prompt: string;
  correctAnswer: string;
  alternatives: string[];
}

interface MultipleChoiceExercise extends BaseExercise {
  type: 'multiple_choice';
  prompt: string;
  options: string[];
  correctOptionIndex: number;
}

interface FillBlankExercise extends BaseExercise {
  type: 'fill_blank';
  sentence: string;         // Contains "___" placeholder
  correctWords: string[];
}

interface WordBankExercise extends BaseExercise {
  type: 'word_bank';
  prompt: string;
  correctSentence: string;
  distractorWords: string[];
}

interface ListeningExercise extends BaseExercise {
  type: 'listening';
  audioUrl: string;
  correctTranscript: string;
}

interface SpeakingExercise extends BaseExercise {
  type: 'speaking';
  targetSentence: string;
  phoneticHints: string | null;
}

interface MatchingExercise extends BaseExercise {
  type: 'matching';
  pairs: { left: string; right: string }[];
  leftColumnLabel: string;
  rightColumnLabel: string;
}

interface ImageSelectExercise extends BaseExercise {
  type: 'image_select';
  word: string;
  images: { url: string; alt: string }[];
  correctImageIndex: number;
}

type Exercise =
  | TranslationExercise
  | MultipleChoiceExercise
  | FillBlankExercise
  | WordBankExercise
  | ListeningExercise
  | SpeakingExercise
  | MatchingExercise
  | ImageSelectExercise;
```

## 6.11 DTOs & Request/Response Mapping

### 6.11.1 Frontend ↔ API DTO Mapping

The frontend maintains its own models that map to/from API DTOs:

```typescript
// API DTO (what the server returns)
interface LearnerApiDto {
  id: string;
  username: string;
  email: string;
  display_name: string;        // snake_case from API
  avatar_url: string | null;
  join_date: string;
  last_active_at: string;
  total_xp: number;
}

// Frontend Model (what components use)
interface Learner {
  id: string;
  username: string;
  email: string;
  displayName: string;         // camelCase in frontend
  avatarUrl: string | null;
  joinDate: Date;              // Converted to Date object
  lastActiveAt: Date;
  totalXp: number;
}

// Mapper
class LearnerMapper {
  static fromApi(dto: LearnerApiDto): Learner {
    return {
      id: dto.id,
      username: dto.username,
      email: dto.email,
      displayName: dto.display_name,
      avatarUrl: dto.avatar_url,
      joinDate: new Date(dto.join_date),
      lastActiveAt: new Date(dto.last_active_at),
      totalXp: dto.total_xp,
    };
  }

  static toApi(model: Partial<Learner>): Partial<LearnerApiDto> {
    return {
      ...(model.displayName !== undefined && { display_name: model.displayName }),
      ...(model.email !== undefined && { email: model.email }),
    };
  }
}
```

### 6.11.2 Convention: Case Mapping

- **API responses**: `snake_case` (Python/Ruby backend convention)
- **Frontend models**: `camelCase` (TypeScript convention)
- A global HTTP interceptor can automatically convert between cases, or explicit mapper classes are used per feature.

### 6.11.3 Nullable Fields

- API fields that can be null are typed as `T | null` in both DTOs and models.
- The frontend never uses `undefined` to represent "no value" from the API — always `null`.
- Optional request fields (not required) use `?` in the interface.

## 6.12 Error Handling Patterns

### 6.12.1 API Error Response Structure

All API errors follow a consistent structure:

```typescript
interface ApiErrorResponse {
  errors: ApiError[];
}

interface ApiError {
  code: string;           // Machine-readable error code
  message: string;        // Human-readable message (English)
  field?: string;         // Field name for validation errors
  details?: Record<string, any>;  // Additional context
}
```

### 6.12.2 Error Code Reference

| Code | HTTP Status | Description | Frontend Handling |
|---|---|---|---|
| `VALIDATION_ERROR` | 422 | Field validation failed | Show inline field error |
| `NOT_FOUND` | 404 | Resource not found | Show 404 page or toast |
| `CONFLICT` | 409 | Concurrent modification | Show conflict dialog |
| `UNAUTHORIZED` | 401 | Invalid/expired token | Redirect to login |
| `FORBIDDEN` | 403 | Insufficient permissions | Show access denied |
| `RATE_LIMITED` | 429 | Too many requests | Show "please wait" message |
| `INCOMPLETE` | 422 | Resource missing required data | Show checklist of missing items |
| `DUPLICATE` | 409 | Unique constraint violation | Show "already exists" error |
| `DEPENDENCY` | 422 | Cannot delete due to dependencies | Show list of dependent resources |
| `INTERNAL_ERROR` | 500 | Server error | Show generic error with retry |

### 6.12.3 Error Mapping in Services

```typescript
@Injectable({ providedIn: 'root' })
export class CourseService {
  private api = inject(ApiService);

  publishCourse(id: string): Observable<Course> {
    return this.api.post<Course>(`/courses/${id}/publish`, {}).pipe(
      map((response) => CourseMapper.fromApi(response.data)),
      catchError((error: HttpErrorResponse) => {
        if (error.status === 422) {
          const apiErrors = error.error?.errors || [];
          const incomplete = apiErrors.find((e: ApiError) => e.code === 'INCOMPLETE');
          if (incomplete) {
            return throwError(() => new IncompleteError(incomplete.details?.['missing'] as string[]));
          }
        }
        return throwError(() => error);
      }),
    );
  }
}
```
